# Fill Zoom

영상의 검은 여백을 잘라내고 재생기 화면을 채우는 크롬 확장 프로그램입니다.

## 설치

`chrome://extensions` 에서 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드합니다**
로 이 폴더를 고릅니다. 1.0 을 이미 설치했다면 지우고 다시 로드해 주세요.
파일 구성이 바뀌었습니다.

## 조작 수단

전체화면에서는 크롬의 확장 팝업을 열 수 없으므로, 조작 수단을 페이지 안에도 뒀습니다.
페이지 안의 조작판은 표시 단계가 두 개입니다.

- **재생기 조작줄의 버튼**은 조작판을 아예 띄울지 말지를 정합니다. 기본값은 띄우는
  쪽이고, 이 선택만 저장합니다. 조작줄은 화면 아래에 있어 자주 오갈 자리가 아닙니다.
- **띄운 조작판은 오른쪽 위의 작은 단추**로 시작합니다. 그 단추를 눌러야 본 패널이
  펼쳐집니다. 접힌 상태가 기본이고, 펼친 상태는 저장하지 않습니다. 자주 하는
  펼치고 접기가 패널과 같은 자리에서 끝나므로 세로로 긴 창에서도 손이 멀리 가지
  않습니다.
- 작은 단추는 재생기가 조작줄을 감출 때 같이 사라졌다가, 마우스를 움직이면
  다시 나타납니다. 채움이나 회전이 걸려 있으면 파랗게 표시됩니다.
- `Shift+A` 로 펼치고 접습니다. `Shift+S` 로 조작판 자체를 띄우고 감춥니다.
  유튜브와 크롬 어느 쪽도 이 조합들을 쓰지 않습니다.
- `Shift+Z` 로 채움 방식을 차례로 바꾸고, `Shift+R` 로 회전을 바꾸고,
  `Shift+X` 로 둘 다 되돌립니다.
- `Alt+Z`, `Alt+X` 는 브라우저 수준의 단축키라서 페이지에 초점이 없어도 동작합니다.
  `chrome://extensions/shortcuts` 에서 바꿀 수 있습니다.
- 확장 팝업은 전체화면이 아닐 때 씁니다. 페이지 안 패널과 같은 미리보기를 씁니다.

패널은 전체화면 요소 안에 붙기 때문에 전체화면에서도 보입니다. 패널 안의 클릭과
키 입력은 재생기로 새어 나가지 않으므로, 조작 중에 영상이 멈추지 않습니다.

## 네 가지 채움 방식

| 방식 | 하는 일 |
| --- | --- |
| 원래 크기 | 아무것도 하지 않습니다. |
| 상하 채움 | 그림의 높이가 재생기 높이와 같아질 때까지 확대합니다. 위아래 띠가 사라지고 좌우가 잘립니다. |
| 좌우 채움 | 그림의 폭이 재생기 폭과 같아질 때까지 확대합니다. 좌우 여백이 사라지고 위아래가 잘립니다. |
| 꽉 채움 | 위 둘 중 큰 배율을 씁니다. 어느 쪽에도 여백이 남지 않습니다. |

## 영상 속 그림 비율

검은 띠에는 두 종류가 있습니다. 재생기가 만들어 낸 띠는 브라우저가 요소 크기로
알 수 있지만, 영상 파일 안에 이미 구워져 들어간 띠는 알 수 없습니다.
16:9 파일 안에 2.39:1 영화가 들어 있는 경우가 여기에 해당합니다.

그래서 **감지** 단추가 있습니다. 재생 중인 화면을 캔버스로 옮겨 위아래와 좌우에서
검은 줄이 몇 줄이나 이어지는지 세고, 어두운 장면을 띠로 착각하지 않도록 0.35초
간격으로 다섯 번 재서 가장 작은 값을 씁니다. 결과를 흔한 비율에 맞춰 `2.39` 같은
값으로 정리합니다. 드롭다운에서 직접 고를 수도 있습니다.

DRM이 걸린 영상은 캔버스 읽기가 막히므로 감지가 실패합니다. 이때는 비율을 직접
고르면 됩니다.

## 0.3.0 에서 바꾼 것

**보이는 영역을 슬라이더 대신 그림으로 고릅니다.** 화면을 채우면 어느 방향인가는
잘려 나가는데, 어디를 남길지를 이전에는 좌우·상하 슬라이더로 정했습니다. 슬라이더를
오른쪽으로 밀면 보이는 창이 왼쪽으로 가므로 방향이 뒤집혀 느껴지는데, 이 감각은
사람마다 달라서 어느 쪽으로 뒤집어도 절반은 어긋납니다. 그래서 방향을 고르는 조작
자체를 없앴습니다. 영상의 작은 사본을 그려 두고, 지금 화면에 나오는 부분을 밝은
상자로 표시하고, 그 상자를 끌어 옮깁니다. 상자 바깥은 어둡게 깔리므로 무엇이
잘리는지도 같이 보입니다. 상자 바깥을 누르면 그 자리로 옮겨 가고, 두 번 누르면
가운데로 돌아갑니다. 방향키로도 옮길 수 있습니다.

미리보기 그림은 `video` 를 캔버스에 그대로 옮겨 그립니다. 픽셀을 되읽지 않으므로
띠 감지가 쓰는 `getImageData` 와 달리 GPU 에서 CPU 로 옮기는 비용이 없습니다.
**단, 캔버스가 가속을 받고 있을 때만 그렇습니다.** 크롬은 넓이가 작은 2D 캔버스를
가속 대상에서 빼는데(256×257 언저리의 문턱), 그러면 `drawImage` 가 디코드된 원본
프레임을 통째로 CPU 로 끌어내린 다음 줄입니다. 1920×1080 을 256×144 로 줄이는 값싼
일이 1920×1080 을 전부 회수하는 비싼 일로 바뀝니다. 그래서 미리보기 캔버스의 넓이
`PREVIEW_MIN_AREA` 는 상한이 아니라 **하한**입니다. 작게 잡을수록 손해입니다.

그리는 시점은 `requestVideoFrameCallback` 이 정합니다. 화면에 실제로 뿌려진 프레임
마다 한 번씩만 불리므로 같은 그림을 두 번 그리는 일이 없고, 영상이 멈추거나 탭이
가려지면 프레임이 나오지 않으니 저절로 멎습니다. 프레임 수를 미리 정해 두지 않습니다.

대신 한 번 그리는 데 실제로 든 시간을 재서 그 20배를 쉽니다. 즉 미리보기가 쓰는
시간을 전체의 5% 아래로 묶습니다. GPU 경로에서는 잰 값이 0에 가까워 사실상 영상
프레임마다 그리고, 어떤 이유로 CPU 로 떨어지면 그 자리에서 시간이 잡히므로 간격이
저절로 벌어집니다. 콘솔에서 `FZ.stats()` 로 실제 값을 볼 수 있습니다.

확장 팝업 쪽은 사정이 다릅니다. 팝업은 다른 문서라 캔버스를 넘길 수 없어서 `toDataURL`
로 **되읽기와 JPEG 부호화를 반드시 거칩니다**. 이쪽만 0.5초 간격을 유지합니다.

**그림 단추**로 이 갱신을 통째로 끌 수 있습니다. 끄면 아무것도 그리지 않고 도식만
남습니다 — 상자와 어두운 부분은 그대로라 조작은 똑같이 됩니다. 이 설정은 페이지 안
패널과 확장 팝업이 함께 쓰고, 어느 쪽에서 바꾸든 바로 따라갑니다.

DRM 이 걸린 영상은 그리기 자체가 막힙니다. 이때도 도식만 남습니다. 교차 출처 영상은
그리기는 되고 되읽기만 막히므로, 페이지 안 패널에서는 보이고 확장 팝업에서만
도식으로 나옵니다.

손잡이는 `ui.js` 위쪽의 `PREVIEW_MIN_AREA`(캔버스 넓이 하한), `COST_SHARE`(비용의 몇
배를 쉴지), `GAP_MAX`(간격 상한) 과 `popup.js` 의 `FRAME_MS`, `FRAME_MAX` 입니다.

**끌기 중 저장.** 상자를 끄는 동안 상태가 초당 수십 번 바뀝니다. 화면은 그때마다
갱신하되 저장은 손을 뗀 뒤 0.3초에 한 번만 합니다.

## 0.2.0 에서 더한 것

**회전.** 바로, 오른쪽 90도, 왼쪽 90도, 180도 네 가지를 단추로 고릅니다.
`Shift+R` 로도 차례로 바꿉니다. 세로로 찍은 영상이 눕혀서 올라온 경우에 씁니다.

회전은 채움 계산보다 먼저 반영됩니다. 90도나 270도로 돌리면 화면에서 차지하는
가로와 세로가 서로 바뀌므로, 채움 배율은 돌린 뒤의 크기를 기준으로 구합니다.
`transform` 은 `translate(...) rotate(...) scale(...)` 순서로 붙는데, CSS 는
오른쪽 끝부터 적용하므로 크기를 먼저 바꾸고, 돌리고, 마지막에 옮깁니다.

**돌리기만 했을 때의 배율.** 채움을 끈 상태에서 90도로 돌리면 배율 1은 쓸모가
없습니다. 1920×1080 영상을 세로로 세우면 1080×1920 이 되어 화면 위아래로
넘칩니다. 그래서 회전이 걸려 있고 채움이 꺼져 있으면 상자 안에 다 들어오는
배율을 씁니다. 세로 영상을 가로 화면에서 온전히 보는 상태가 여기에 해당합니다.
좌우에 검은 여백이 남는 것이 정상입니다.

## 0.1.3 에서 고친 것

**레터박스 위에 놓인 패널이 여전히 안 보이던 문제.** 패널을 합성 층으로 올린 것만
으로는 부족했습니다. 브라우저는 영상 영역과 겹치는 내용이 없으면 영상을 하드웨어
오버레이 평면으로 내보내는데, 그 평면은 영상 바깥까지 채우기 때문에 검은 여백
위에 놓인 내용이 덮입니다. 그래서 패널과 안내 문구를 재생기 전체를 덮는 층 안에
넣었습니다. 이 층은 영상 영역과 반드시 겹치므로 브라우저가 오버레이 경로를 쓰지
못하고 평소대로 합성합니다. 층은 클릭을 통과시키고, 패널이 닫히면 사라집니다.

**아이콘 위치.** 원인은 그림의 크기가 아니라 상자의 크기였습니다. 버튼과 `svg`
어느 쪽에도 확정된 크기가 없어서 `svg` 가 버튼보다 큰 상자를 잡았고, 그 상자
안에서 가운데 정렬된 그림이 버튼 기준으로는 오른쪽 아래로 밀려 보였습니다.
버튼을 48픽셀 너비의 `inline-flex` 로, `svg` 를 24픽셀 정사각형으로 못 박고
가운데 정렬했습니다. 좌표계도 24 단위로 바꿔 그림이 상자를 거의 채웁니다.

## 0.1.2 에서 고친 것

**패널이 재생 중에 눈에서 사라지던 문제.** 재생 중인 영상은 GPU 합성 층으로
올라가고, 확대를 위해 `transform` 을 걸어 두면 더 확실하게 올라갑니다. 이때 평범한
`div` 는 아무리 `z-index` 를 높여도 그 층보다 뒤에 그려지는 경우가 있습니다.
적중 판정은 DOM 순서를 따르므로 단추는 계속 눌리는데 눈에만 안 보이는, 정확히
관찰된 대로의 상태가 됩니다. 패널과 안내 문구에도 `transform: translateZ(0)` 을
줘서 같은 합성 층으로 올렸습니다.

**확대가 저절로 풀리던 문제.** 크기가 바뀌지 않았는데 재생기가 `video` 의
`style` 을 다시 쓰면서 우리 `transform` 을 지우는 경우가 있습니다. 0.1.1 까지는
다시 계산할지 여부를 크기 서명만으로 판단했기 때문에, 지워진 것을 알아채지
못하고 그냥 넘어갔습니다. 일시정지 후 재생이 해결책이 된 이유는 `play` 이벤트가
강제 재적용을 부르기 때문입니다. 이제는 걸어 둔 문자열을 그대로 기억해 두고 매번
대조하며, `timeupdate` 로 초당 네 번쯤 확인합니다. 이 확인은 문자열 비교뿐이라
배치 계산을 일으키지 않고, 어긋났을 때만 다시 겁니다.

**크기를 재는 방식.** 이전에는 `transform` 을 잠시 `none` 으로 돌려 원래 크기를
쟀습니다. 그 사이에 예외가 나거나 중간에 빠져나가면 확대가 풀린 채로 남습니다.
이제는 우리가 건 이동량을 좌표에서 빼는 방식으로 계산하므로, 재는 동안 화면을
건드리지 않습니다.

**강제 재적용이 묻히던 문제.** 한 프레임 안에서 강제 요청 뒤에 일반 요청이 오면
강제 표시가 덮여 사라졌습니다. 이제 한 번이라도 강제가 들어오면 그 프레임은
강제로 처리합니다.

## 0.1.1 에서 고친 것

패널의 단추와 드롭다운이 눌리지 않던 문제를 고쳤습니다. 재생기가 클릭과 키를
가로채지 못하도록 패널 바깥으로 나가는 이벤트를 막아 뒀는데, 그 차단을 캡처
단계에 걸어 둔 탓에 패널 안의 단추까지 이벤트를 받지 못했습니다. 버블 단계로
옮겨서, 패널 안의 요소가 먼저 이벤트를 처리한 뒤에 바깥으로 새는 것만 막습니다.

재생기 버튼 아이콘이 지나치게 크게 보이던 것도 고쳤습니다. 유튜브 아이콘은
36 단위 좌표계 안에서 20 남짓한 크기로 그려지는데, 이전 아이콘은 좌표계를 거의
가득 채우고 있었습니다.

## 0.1.0 에서 고친 것

전체화면에 들어가는 순간 잠깐 확대되었다가 원래 배율로 돌아오던 문제를 고쳤습니다.
원인은 두 가지가 겹친 것이었습니다.

첫째, 전체화면 전환 도중에는 재생기 상자만 먼저 커지고 `video` 요소는 아직 창
모드 크기입니다. 그 순간의 값으로 배율을 구하면 터무니없이 큰 값이 나옵니다.
이제는 `video` 요소가 상자의 가로나 세로 중 한쪽에 닿았는지 확인해서, 닿지 않았으면
자리가 잡히지 않은 것으로 보고 적용을 미룹니다.

둘째, 유튜브가 `video` 요소를 전체화면 크기로 다시 키우고 나면 요소가 상자를 이미
가득 채우므로, 자동 비율에서는 배율이 정확히 1로 계산됩니다. 계산 자체는 맞지만
사용자가 원한 결과는 아닙니다. 검은 띠가 영상 파일 안에 들어 있었기 때문입니다.
감지 기능이 이 경우를 처리합니다. 배율이 1로 나오면 패널이 그 사실과 이유를
문장으로 알려 줍니다.

## 동작 원리

`<video>` 요소에 CSS `transform: translate(...) scale(...)` 을 걸고, 그 위 요소에
`overflow: hidden` 을 줘서 넘치는 부분을 잘라 냅니다. 재생기 크기가 바뀌면
`ResizeObserver` 와 `MutationObserver` 가 감지해 다시 계산하고, 전체화면 전환
직후에는 0.05초에서 0.9초 사이에 다섯 번 더 확인해서 자리가 잡힌 값을 잡습니다.

## 파일

- `core.js` — 대상 찾기, 배율 계산, 적용, 띠 감지
- `ui.js` — 재생기 버튼, 전체화면에서 쓰는 패널, 키보드
- `popup.js` / `popup.html` / `popup.css` — 확장 팝업
- `background.js` — 브라우저 단축키를 탭으로 전달

## 알려진 한계

확장에서 시작한 전체화면 전환은 브라우저가 막을 수 있습니다. 전체화면은 사용자
제스처를 요구하는데, 팝업에서 보낸 메시지는 페이지 쪽 제스처로 인정되지 않기
때문입니다. 팝업의 전체화면 단추는 유튜브의 전체화면 버튼을 눌러 보고 결과를
확인한 뒤, 막혔으면 그렇다고 알려 줍니다. 재생기 버튼에서 여는 패널은 진짜
클릭이므로 이 제약을 받지 않습니다.

유튜브, 넷플릭스, 트위치, 비메오는 재생기 요소를 선택자로 지정해 뒀습니다. 그 밖의
사이트에서는 조상 요소를 훑어 추측하므로 기준이 어긋날 수 있습니다.
`core.js` 위쪽의 `SITE_BOX` 배열에 한 줄 추가하면 정확해집니다.

`<video>` 요소에 사이트가 이미 `object-fit: cover` 를 걸어 둔 경우에는 계산 전제가
맞지 않습니다.
